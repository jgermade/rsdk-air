# Native multi-engine launcher

## 2026-11-20 — Kickoff and technology decision

Context:

- Request: one binary bundling the RSDK engines (v3, v4, v5U) and Sonic 3 A.I.R.,
  asking at startup which game to play. Targets: Windows, Linux, macOS, Android.
- Reviewed github.com/wasm-gaming: `rsdkv3-wasm`, `rsdkv4-wasm`, `rsdkv5-wasm`,
  `sonic3air-wasm` and `engine-specs` (the shared JS engine contract). Those packages
  are WebAssembly builds of the same C++ engines; this project is the native version.
- Notes from those READMEs: the engines bake no game data (the player provides
  `Data.rsdk` / the S3&K ROM); RSDKv3 and RSDKv5 cannot restart in-process.

Decisions:

- C++20 + CMake + SDL2 for everything; Dear ImGui for the launcher UI.
- Each engine is a shared library with hidden symbols and a small C ABI
  (`rsdkair_engine_games`, `rsdkair_engine_main`).
- One engine per process: desktop launcher runs `rsdk-air --game <id>` as a child
  process; Android uses a separate `:game` process for `GameActivity`.
- Rejected alternative: wrapping the existing wasm packages in Tauri 2. It would be faster
  to build, but slower on WebKitGTK and older Android WebViews, and audio, storage and
  WASM threads are harder to get right in a WebView.

Plan written in `ROADMAP/2026-11-20/` (`overview.md`, `architecture.md`).

Open questions:

- Upstream forks/commits to pin for each engine (RSDKv3/v4 native: likely the
  RSDKModding decompilations).
- Licenses: all engines are non-commercial with their own terms; review before release.

## 2026-11-20 — Upstreams pinned and license review

- Upstreams: latest stable tag of each official repo (RSDKModding RSDKv3/v4 `1.3.3`,
  RSDKv5 and Sonic Mania `v1.1.1`, Eukaryot/sonic3air `v26.03.28.0-stable`). Details in
  `ROADMAP/2026-11-20/upstreams-and-licensing.md`.
- Finding: Sonic 3 A.I.R. is now **GPL-3.0**, while the RSDK and Mania decompilations have
  non-commercial custom licenses. The two cannot be combined into one program; they can be
  shipped side by side as separate programs (aggregation).
- Consequence: "one engine per process, never in the launcher process" is now a legal
  requirement as well as a technical one.
- RSDK licenses require `RETRO_DISABLE_PLUS=ON` (DLC off by default) in every pre-built
  binary, credits, and no game assets.
- Open: license for our own code. Recommended MIT or zlib (compatible with both sides);
  waiting for the owner's choice.

## 2026-11-20 — Own-code license and what RETRO_DISABLE_PLUS does

- Owner: the project will be published as open source, non-profit, and left the license
  to the agent's advice. Chosen: **MIT** for our own code (`LICENSE`). Third-party engines
  keep their own licenses.
- Read the upstream code for `RSDK_AUTOBUILD` (set by the CMake flag `RETRO_DISABLE_PLUS`):
  it only removes Plus/Origins Plus DLC content — Knuckles and Amy in Sonic CD, Amy in
  Sonic 1/2, Mighty/Ray/Encore in Mania. Base games are unaffected.
- To check: the wasm-gaming `rsdkv5-wasm` app offers Mighty and Ray "with Plus"; whether its
  published build sets `RSDK_AUTOBUILD` was not verified.

## 2026-11-20 — Plus DLC for personal builds

- Owner wants to build with Plus enabled for personal use in a private copy of the repo.
  Allowed by the RSDK licenses (they only restrict pre-built executables given to others).
- Decision: CMake option `RSDKAIR_ENABLE_PLUS` (default OFF) plus a `workflow_dispatch`
  input `enable_plus` that only takes effect when the repository is private. Plus builds
  are never released. Details in `ROADMAP/2026-11-20/upstreams-and-licensing.md`.
- Reason for the private-only guard: artifacts of public repos are downloadable by any
  GitHub user.

## 2026-11-20 — CI and release workflow split

- Owner proposed running the build workflow only for tags/releases from `main`, with no
  pull request trigger, so nobody else can run it in the public repo.
- Finding: that limits who can run *our* workflow, but PR runs use the workflow files from
  the PR branch, so a fork could add its own. The real guard is the repository setting
  "require approval for all external contributors", plus a `v*` tag ruleset and a
  `release` environment with a required reviewer.
- Decision: `ci.yml` (PRs and pushes, Plus always off, no downloadable binaries) and
  `release.yml` (tags `v*` from `main` and manual runs; `enable_plus` only in private
  repos). Recorded in `ROADMAP/2026-11-20/upstreams-and-licensing.md`.

## 2026-11-20 — Single owner-run workflow

- Owner: only they will run workflows. Replaces the `ci.yml`/`release.yml` split with one
  `build.yml` (manual runs from `main` and `v*` tags only, no PR triggers). The `release`
  environment is dropped; the fork-approval setting and the `v*` tag ruleset stay.

## 2026-11-20 — build.yml + release.yml

- Owner's design, accepted with adjustments:
  - `build.yml`: push to `main` (no PR trigger) + `workflow_call`; runs tests and builds.
  - `release.yml`: manual; inputs `bump` (major/minor/patch) and `enable_plus` (default
    off); calls `build.yml`, creates tag + release with the builds, deploys the landing to
    GitHub Pages.
- Adjustments: `enable_plus` fails fast on a public repo (license) and skips the Pages
  deploy (Pages is always public); tag created only after a green build; `main` branch
  ruleset so only the owner pushes. Details in
  `ROADMAP/2026-11-20/upstreams-and-licensing.md`.
- New piece of scope: a landing page in `site/`.

## 2026-11-20 — Owner confirmations

- Only the owner merges into `main`.
- `enable_plus` on `release.yml` will only be used in the owner's private copy. The
  public-repo guard stays as a safety net against a mistaken click.

## 2026-11-20 — Save slots and pause menu like play.germade

- Owner likes the save slots and pause menu of play.germade. Those screens come from the
  wasm-gaming engine apps (`rsdkv4-wasm`, `rsdkv5-wasm` `src/app/app.js`), following
  engine-specs `UX.md`; play.germade itself only has a generic Continue/Restart/Back menu.
- Proposed native design (`ROADMAP/2026-11-20/game-menus.md`): load-game screen in the
  launcher process, reading save files directly (no engine loaded); pause menu as a Dear
  ImGui overlay in the game process, through a planned engine ABI v2 (host frame/event
  callbacks, optional pause/start_slot/screens functions). The wasm builds' C++ save bridges
  can be ported to the native modules.
- The wasm apps' zone portraits and character art are SEGA content: not shipped. Start with
  neutral art; later extract art from the player's Data.rsdk.
- Pending owner confirmation of this design.
