## 2026-11-21 — First release run failed on Android

- Owner squashed PR #2 into main and ran `release.yml` (version 0.0.1). linux-x64,
  windows-x64 and macos-arm64 built, tested and packaged; the Android job failed after
  9 s, so `publish` and `pages` were skipped.
- Cause: Gradle could not resolve `org.jetbrains.kotlin:kotlin-stdlib-jdk8:1.9.20` (needed
  by the Android Gradle Plugin 8.7.3) from any repository (Google, Maven Central, Gradle
  plugins). Nothing in our code or versions changed. Second occurrence today: the same
  kind of failure hit `error_prone_annotations:2.18.0` on `8aa2fb8`, and a re-run passed.
- Fix in `android.yml`:
  - `actions/setup-java` with `cache: gradle` (keyed on the Gradle files and the wrapper
    properties), so runs reuse downloaded dependencies.
  - The Build APK step retries Gradle up to 3 times, 30 s apart, only when the log shows a
    download failure (`Could not resolve|find|GET|download`); any other failure, such as a
    compile error, fails at once. `set -o pipefail`, since `gradlew | tee` would otherwise
    report tee's status (the default shell has no pipefail).
- Checked the retry logic locally with a fake gradlew: a download failure is retried and
  then passes (2 calls); a compile error fails on the first call. `actionlint` passes.
- Branch `claude/exciting-carson-04njuk` restarted from main (the old one was deleted
  after the merge).
